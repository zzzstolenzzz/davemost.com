Project

Doodle Chess

Chess drawn in ballpoint pen. Two approved players move, anyone can watch live, and each move pings the other player's phone.

  • Live to watch
  • Installable web app
  • Push alerts

Purpose

A turn-based chess game that works across devices, feels hand-made, and tells you when it's your move.

It is a small full-stack system: a static front end, a realtime database as the shared board, and a Cloudflare Worker for the parts that need a server.

What it does

  • Realtime play. Moves appear on the other screen as they happen. Spectators see the same live board.
  • Full chess rules. Legal moves, check, checkmate and a promotion picker, via chess.js.
  • Hand-drawn look. SVG pieces run through a displacement filter. Board lines and highlights are drawn with a seeded "shaky pen" generator. One side is blue ink, the other red.
  • Captured pieces go to "jail". Each player has a jail with hand-drawn bars. Captured pieces are scribbled out and tumble away.
  • Polish. Highlighter-style marks on selected and last-move squares, idle pieces that hop and wiggle, a splat on checkmate, and respect for reduced-motion settings.
  • Synthesized sound. Every sound effect is generated with Web Audio. There are no audio files. A mute toggle is remembered.
  • Replay and undo. Replay re-animates the last move locally. A player can take back their own last move until the opponent replies.
  • Move alerts. Optional push notifications. On iPad and iPhone it guides you through Add to Home Screen first.
  • Connection status. An "offline - reconnecting" banner appears when the connection drops.

Security & privacy

  • Anyone can watch, two accounts can play. The game is publicly readable. Writes are limited to two approved Google accounts, enforced by database rules, not just the page.
  • Turn order is enforced server-side. The rules let each account write only when the stored position says it is that side's turn. A player can undo only their own last move.
  • Shape is validated. The rules check the record has the required fields, a short position string, and a move counter that changes by one (or resets).
  • Deny by default. Everything outside the game record is closed at the database root.
  • The Worker can't be spammed or forged. /chess-move takes no input. It reads the public game state itself and ignores a move it has already announced.
  • Alert sign-up needs proof. /chess-subscribe verifies the caller's Firebase sign-in token with Google and rejects anyone who isn't one of the two players. Subscriptions are capped per player.
  • No secrets in the browser. The push key shipped to the page is the public half of a key pair.

Chess legality itself is checked in the client. The rules guard whose turn it is and what shape the data has. That is a deliberate fit for two known players.

Notable engineering decisions

  • Transactions for moves. A move commits only if the board is still what the player saw. If the other side moved first, the move aborts and the board re-syncs.
  • Animate small, re-render big. If an update is exactly one move ahead, the piece slides. Anything else triggers a full redraw, so a missed update self-heals.
  • One-step undo from stored history. Each record keeps the previous position, so undo is a safe, rule-checked write.
  • Web Push written by hand. The Worker encrypts and signs push messages using only the platform's WebCrypto API (the standard Web Push RFCs), with no push library.
  • Sign-in that survives iOS. Popups are unreliable on iPhone, iPad and installed home-screen apps, so the app switches to a redirect flow there, with a friendly error if sign-in is blocked.
  • Service worker kept minimal. It handles notifications only. There is no caching or offline logic to go stale.
