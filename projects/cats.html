Project

Cat Adventure

A 3D cat game that runs in a mobile browser: explore an island, find fish, shop for upgrades, and see other players live.

  • Private family game
  • Touch-first 3D
  • Live multiplayer

Purpose

A private 3D game for my family, playable on a tablet with no install, where only approved players can get in.

It is a showcase for two things: real-time 3D graphics that stay smooth on mobile hardware, and a login system that keeps a young audience safe without making sign-in painful.

What it does

  • Free-roam 3D island. Third-person cat, pond, bridge, cottage, trees, butterflies and wind-blown grass.
  • Goals and rewards. Find 10 hidden fish, collect coins, and earn a bonus for finding them all.
  • Shop. Hats, glasses, neck and back items, fur "looks" and effects across four rarity tiers, plus six upgrades with three levels each (speed, jump with a double-jump, coin magnet, fish radar, glide, lucky paw).
  • Live multiplayer. Players see each other's cats move. Off-screen pointers and a mini-map help find the other player.
  • Touch-first controls. Floating joystick, jump button and drag-to-orbit camera, with keyboard and mouse as a fallback.
  • Saved progress. Fish, coins, owned items, equipped items and upgrades are saved per player.
  • Graphics settings. Auto, High or Low quality.

Security & privacy

This is a private family game. The page shows a locked screen to anyone who isn't an approved player, and it is excluded from search engines. Nothing about the players or their data is shown here.

  • PINs are checked on the server. They are never shipped to the browser. They live only as Worker secrets.
  • Constant-time comparison. The PIN check compares hashes byte by byte so response timing leaks nothing.
  • Brute-force lockout. After five wrong tries a player is locked out for 15 minutes. There is also a per-IP hourly cap. One Durable Object holds all counters so every attempt is decided atomically.
  • A real identity, not a shared password. A correct PIN earns a Firebase custom token (an RS256-signed JWT) minted by the Worker. After that, the database sees a normal signed-in user.
  • Database rules are the real gate. Only approved accounts can read the game data. A player can write only to their own records, and every write is validated for type, range and allowed fields.
  • Fails closed. If the Worker's configuration is missing or malformed, it returns "unavailable" instead of letting anyone in.
  • CORS is locked to this site (and localhost for development).

Notable engineering decisions

  • Security that fits the audience. A 4-digit PIN is weak on its own, but it is easy for a child. So the safety comes from the server-side lockout and the database rules, not from the PIN staying secret.
  • No art assets. The cat, island, trees, accessories and textures are generated in code. The cat is a single smooth skinned mesh built from an implicit surface, with a procedural skeleton. No 3D model files are downloaded.
  • Mobile performance first. Instanced meshes, merged geometry, one-draw-call particles, and a quality system that lowers render resolution when frame time slips. It falls back to the Low tier only in Auto mode.
  • Two render paths. High adds post-processing (bloom, FXAA, colour grade, vignette, ACES tone mapping) and bigger shadow maps. Low draws straight to the screen.
  • Presence per page load. The same account on two devices shows two cats. Disconnects clean up automatically, and stale remote cats time out.
  • Data-driven shop. Items, prices, rarities and upgrades are plain data, so tuning the game never touches game logic.
